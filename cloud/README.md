# מחירון בענן — אתר ציבורי בלי שרת ובלי עלות חודשית

האתר שב־`site/` הוא אתר סטטי. אין מאחוריו שרת: הדפדפן של הלקוח קורא את קובץ
מסד הנתונים ישירות מ־Cloudflare R2, חתיכות קטנות בכל פעם, לפי מה שהשאילתה צריכה.

| | |
|---|---|
| האתר | Cloudflare Pages, נמשך אוטומטית מ־GitHub |
| הנתונים | Cloudflare R2, קובץ אחד בגודל 1.95GB |
| עלות | 0 ש"ח לחודש |

## למה זה חינם

R2 נותנת 10GB אחסון ו**תעבורה בלי הגבלה ובלי חיוב**. מה שכן נספר הוא מספר
הבקשות: 10 מיליון בחודש. ביקור טיפוסי באתר צורך כ־53 בקשות, כלומר כ־188,000
ביקורים בחודש נכנסים במכסה החינמית. מעבר לכך המחיר הוא 0.36 דולר למיליון בקשות.

## הקמה חד־פעמית

**1. חשבון ודלי.** נרשמים ב־cloudflare.com, נכנסים ל־R2 ויוצרים דלי בשם `mehiron`.

**2. גישה ציבורית.** בהגדרות הדלי, תחת Public access, מפעילים `r2.dev` או מחברים
דומיין. חשוב גם להוסיף מדיניות CORS שמתירה לאתר לקרוא טווחי בתים:

```json
[{ "AllowedOrigins": ["*"],
   "AllowedMethods": ["GET", "HEAD"],
   "AllowedHeaders": ["range"],
   "ExposeHeaders": ["content-length", "content-range", "accept-ranges"] }]
```

**3. מפתחות.** ב־R2 בוחרים Manage API Tokens ויוצרים מפתח עם הרשאת כתיבה.
מעתיקים את הפרטים לקובץ `cloud/r2_config.json` לפי `r2_config.example.json`.
הקובץ הזה לא נכנס לגיט ואסור לשתף אותו.

**4. כתובת המסד.** ב־`site/config.js` מחליפים את `dbUrl` בכתובת הציבורית
של הקובץ, למשל `https://pub-xxxx.r2.dev/mehiron.db`.

**5. האתר.** ב־Cloudflare Pages בוחרים Connect to Git, מצביעים על המאגר,
ומגדירים את תיקיית הפלט `site`. אין פקודת בנייה.

## עדכון יומי אוטומטי

מתקינים פעם אחת:

```
cloud\install_task.bat
```

מכאן העדכון רץ לבד כל יום ב-09:00. אם המחשב היה כבוי באותה שעה, הריצה
מתבצעת בהדלקה הבאה ולא מדלגת על היום.

**למה 09:00.** נספרו שעות הפרסום של קובצי המחירים: הרשתות מפרסמות כמעט
את הכול בין חצות לשמונה בבוקר (746 קבצים בחצות, 467 בחמש). אחר הצהריים
כמעט ריק. הרצה מוקדמת יותר הייתה מפספסת את מי שמפרסם לקראת הבוקר.

**כמה זמן זה לוקח.** נמדד על ריצה מלאה שהופעלה על ידי לוח המשימות:
הורדה 85 דקות, אינדקס 5, בניית מסד הענן 5, והעלאה 3 - **כשעה ורבע עד
שעה וחצי**. ההורדה היא רוב הזמן, והיא תלויה בכמה רשתות מגיבות לאט. אין
צורך לשבת מול המחשב.

### מה קורה בריצה

```
הורדה → אינדקס → בניית מסד ענן → העלאה → אימות → פרסום לגיט → ניקוי
```

הסדר אינו שרירותי:

- **`site/config.js` מתעדכן רק אחרי שההעלאה אומתה מול הדלי.** אחרת כישלון
  באמצע היה מפנה את האתר לקובץ שלא קיים, כלומר אתר שבור במקום אתר שמציג
  את נתוני אתמול.
- **הניקוי רץ רק אחרי דחיפה מוצלחת לגיט.** כל עוד הדחיפה לא עברה, האתר
  החי עדיין מצביע על הגרסה הקודמת, ומחיקתה הייתה שוברת אותו.
- הניקוי גם מקבל במפורש את המפתח שהאתר חי עליו ולא ייגע בו, כי שתי דחיפות
  כושלות ברצף היו הופכות אותו לשלישי בוותק — ולכן לקורבן.

### כשמשהו נכשל

מופיע על שולחן העבודה קובץ בשם `מחירון - צריך טיפול.txt` שמסביר מה קרה.
הוא נמחק לבד ברגע שעדכון מצליח.

הודעה בקובץ ולא בחלון קופץ, כי נמדד שתהליך שנפתח על ידי לוח המשימות במחשב
הזה נתקע על `import ctypes` — כלומר חלון שהיה אמור להופיע פשוט לא הופיע.
קובץ נכתב בלי שום ספרייה חיצונית ולכן אינו יכול להיתקע, והוא גם נשאר עד
שמטפלים בו במקום להיסגר ולהישכח.

### לבדוק מצב בכל רגע

```
status.bat
```

מציג את התפוסה בענן קובץ-קובץ, העלאות שנקטעו, על איזה קובץ האתר מצביע
והאם הוא קיים, גודל המסד המקומי וקצב הגידול, ותוצאת הריצה האחרונה.
הפקודה קוראת בלבד ואינה משנה דבר.

### הרצה ידנית

```
cloud\deploy.bat
```

מריץ את אותם שלבים בדיוק, בלי ההורדה. אותו קוד משמש את שני המסלולים כדי
שלא יתפצלו ויתחילו להתנהג אחרת זה מזה.

## שמירה על מכסת האחסון

המכסה החינמית של R2 היא 10 ג'יגה. ההעלאה נעצרת מעצמה אם היא תעבור 9,
ולפני כל העלאה נמדד השיא הצפוי — לא המצב הסופי, כי בזמן ההעלאה קיימים
בדלי גם הקובץ הישן וגם החדש.

התפוסה היציבה היא כ-3.7 ג'יגה: שתי גרסאות של כ-1.85 כל אחת. היא אינה
גדלה עם הזמן, כי קובץ ההגשה מכיל רק חלון של שבעה ימי מחירים ובלי טבלת
ההיסטוריה — גודלו נגזר ממספר הסניפים והמוצרים, לא ממספר הימים שנצברו.

**הסיכון היחיד שיכול למלא את הדלי הוא העלאות שנקטעו.** החלקים שכבר עלו
ממשיכים לתפוס אחסון ואינם מופיעים ברשימת הקבצים. ל-R2 יש כלל ברירת מחדל
שמבטל אותן אחרי שבעה ימים, אבל עד אז כל ניסיון שנכשל תופס עד 1.85 ג'יגה
וחוסם את ההעלאה של מחר. לכן כל ריצה מבטלת אותן בעצמה בהתחלה.

הביטול מזהה מה להשאיר **לפי מפתח ולא לפי מזהה העלאה**, וזה לא עניין של
נוחות: נמדד ש-R2 מחזירה `UploadId` שונה בכל קריאה לרשימה עבור אותה העלאה
עצמה. שלוש קריאות רצופות החזירו שלושה מזהים שונים, ולכן השוואה למזהה
השמור אצלנו הייתה מבטלת דווקא את ההעלאה שאנחנו באמצע המשכתה.

## הדיסק המקומי

`prices.db` גדל כל יום, כי `price_history` נצברת לפי תכנון. אין מה למחוק:
הרשתות אינן שומרות ארכיון, וההיסטוריה אינה ניתנת לשחזור.

`status.bat` מציג את קצב הגידול הנמדד ואת מספר השנים שנשארו לפי המקום
הפנוי. הריצה היומית מסרבת להתחיל מתחת ל-15 ג'יגה פנויים, וההודעה על
שולחן העבודה מופיעה כבר ב-25.

### למה לכל גרסה יש שם משלה

הקובץ עולה בשם כמו `mehiron-20260903-e3d5eb7f.db`: התאריך שבנתונים ועוד
חתימה קצרה. זה לא נוי.

הדפדפן קורא את המסד בחתיכות ושומר אותן במטמון. אם מחליפים את הקובץ באותה
כתובת, לקוח שכבר טעון מערבב חתיכות משתי גרסאות, ו-SQLite מדווח
`database disk image is malformed`. זה קרה בפועל.

שם ייחודי לכל גרסה פותר את זה לגמרי, ולכן גם מותר לשלוח
`Cache-Control: immutable` ולתת לדפדפן לשמור את החתיכות לצמיתות.

הסקריפט משאיר את הגרסה הקודמת בדלי, כדי שלקוח שנמצא באמצע שימוש לא ייקטע
כשעולה גרסה חדשה. שתי גרסאות תופסות כ-4 ג'יגה מתוך 10 החינמיים.

## למה האתר מהיר למרות שהמסד הוא 1.95GB

| מסך | בקשות | הורדה | זמן |
|---|---|---|---|
| פתיחה | 13 | 428KB | 0.5 שנ' |
| מסך הבית | 0 | 0 | מיידי |
| חיפוש | 10–26 | 24–124KB | 0.2–0.7 שנ' |
| עמוד מוצר | 21 | 356KB | 0.6 שנ' |
| סל | 16 | 336KB | 0.5 שנ' |
| בורסה | 0 | 0 | מיידי |

שלוש החלטות עשו את ההבדל:

**מה שזהה לכולם מחושב מראש.** מסך הבית, רשימת הבורסה, רשימת הערים ורשימת
הסניפים נשמרים כ־JSON בתוך המסד בזמן הבנייה. הם עולים בפתיחה ואחר כך לא
נדרשת אף בקשה. קודם מסך הבית לבדו הוריד 4.8 מגה.

**רשימת הסניפים נטענת לזיכרון.** בלעדיה כל עמוד מוצר היה מבצע 1,727 גישות
אקראיות למסד רק כדי לצרף שם עיר לכל מחיר.

**אינדקס החיפוש מסודר לפי פופולריות.** השורות הוכנסו אליו לפי מספר סניפים
יורד, ולכן `LIMIT 6` בלי מיון מחזיר כבר את הנפוצים ביותר ועוצר. עם `ORDER BY`
המנוע נאלץ לקרוא את כל רשימת ההתאמות: חיפוש המילה "חלב" הוריד כך 44 מגה.
התוצאות זהות בשתי השיטות, ונבדק שהן זהות.

## מגבלות

- **קריאה בלבד.** אין הרשמה, אין שמירת נתונים בצד השרת. הסל נשמר בדפדפן.
- **המסד מתעדכן רק כשמריצים `deploy.bat`.** אין עדכון אוטומטי.
- **הספרייה `sql.js-httpvfs` אינה מתוחזקת באופן פעיל.** היא עובדת, והעתק
  שלה שמור ב־`site/vendor/` כדי שהאתר לא יישבר אם היא תיעלם מהאינטרנט.

## בדיקה מקומית לפני העלאה

```
python cloud\build_cloud_db.py --page-size 4096
copy cloud\mehiron-4096.db site\mehiron.db
python cloud\range_server.py --port 8778 --delay 20
```

`--delay 20` מוסיף השהיה מדומה של 20 מילישניות לכל בקשה, כדי שהמדידה תשקף
אינטרנט אמיתי ולא localhost. הכתובת: `http://127.0.0.1:8778/`.

מונים חיים: `http://127.0.0.1:8778/__stats`.
